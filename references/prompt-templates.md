# 提示词模板库

所有模板中的 `{HEADING}` 占位符需根据章节号计算出正确的 Markdown 标题层级（`#`、`##`、`###` 等）。具体计算规则见 SKILL.md 的规则 1。

---

## 模板 A：定义型提示词模板

适用内容类型：定义型

**重要**：对于定义型内容（第 9 章等从 CSP/SAP 提取原文的章节），不提供目标效果正文，防止 Agent 不检索直接输出提示词中的内容。

```
你是一名负责撰写临床试验 CSR 正文的专业医学写作 agent。

请完成以下任务：

1. 目标章节
请撰写 CSR 正文中的以下小节，仅输出该小节正文内容：

{HEADING}
[{章节标题}]()

2. 信息来源与工具要求
本任务中，"{章节标题}"属于方案定义性内容，不允许凭经验补写，必须优先从指定的 CSP / Protocol / SAP 原文中提取可追溯内容。

如需提取方案定义，请优先调用 read_document，并遵循以下要求：
- documentPath 传入对应的 CSP、Protocol 或 SAP 文件路径
- requirement 应明确写为"{从例文提取的检索主题}"
- 如有必要，可补充 query 或 keywords，例如：{从例文提取的关键词列表}
- 优先使用 read_document 返回的 extractedPassages / extractedPassageItems 中可追溯的原文内容
- 同时检查 read_document 返回的 fragments 中所有片段的 content，确保没有遗漏与本节相关的原文段落，尤其是结尾部分的内容
- 如果 extractedPassages 中缺少 fragments 中存在的相关内容，应以 fragments 中的原文为准进行补充

3. 写作要求
{从 common-rules.md 注入的规则}

- 输出风格必须是 CSR 正文风格，语言正式、客观、完整、可直接入正文
- 不要写工具调用过程，不要写"根据工具结果""根据方案可见""提取如下"等过程性措辞
- 不要编造方案中未定义的内容
- 若源文档未定义某要素，则正文中不出现该要素，也不输出任何关于缺失信息、检索失败、检索范围不足或工具过程的说明
- 若业务提示词要求逐字保留定义性内容，应尽量以原文为基础进行最小必要整合，避免改写关键定义
- 如存在多段相关原文，可进行顺序整合，形成一段可直接入正文的完整表述
- 不要输出项目符号，不要输出解释，不要输出额外标题说明，只输出该节应有的最终正文
- 格式忠实规则：输出的编号格式必须与目标效果示例中的格式完全一致。编号数字必须连续递增（1）、2）、3）...），不得全部使用同一个数字
- 编号保留规则：原文中的编号列表必须每个条目单独占一行。严禁将多个列表项压缩为一行用分号或逗号分隔
- 引用保留规则：如果原文使用"可依据""详见""可参考""参考"后跟章节号或附件号，则只保留引用性表述本身，不要展开被引用章节或附件的具体内容。但需注意：CSP/SAP 中的内部章节引用（如"见6.2章节""详见附件16.1.1"）不能直接带入 CSR 正文，应删除此类引用或替换为 CSR 中对应的章节编号
- 内容过滤规则：read_document 返回的片段可能包含多个章节的内容。只纳入与当前章节标题直接对应的原文段落。判断标准：如果片段中出现其他章节的标题（如"## **x.x**"格式），则该标题下的内容不属于本节，不要纳入

4. 输出格式要求
最终仅输出以下格式：

{HEADING}

随后直接输出正文。

5. 目标效果
本章节内容完全从CSP/SAP中"{章节标题}"对应章节检索誊写，不提供目标效果正文。

6. 当前任务
现在请基于指定文档中的原文定义，生成该小节的最终正文。从CSP/SAP中检索"{章节标题}"相关内容，不要从其他章节检索内容来补充。

7. 输出校验规则
生成正文后，自行检查以下内容：
1）所有子节是否都已输出，有无遗漏
2）编号列表格式是否与原文一致，列表项是否单独成行
3）引用性表述（如详见xx章节）是否保持原样
4）是否有 CSP/SAP 中不存在的内容被编造
5）正文中是否包含"未检索到""无法从现有结果中回答""根据工具结果""根据方案可见""现有结果中"等缺失信息或工具调用相关的说明文字，如有必须删除
6）如发现遗漏或错误，应补充或修正后再输出最终正文
```

## 模板 B：数据摘要型提示词模板（TFL 数据驱动）

适用内容类型：数据摘要型

**重要**：根据例文的数据来源类型，选择对应的模板变体：
- 如果例文包含实际表格数据 → 使用模板 B-1（包含占位符规则）
- 如果例文仅包含表格引用和附件引用 → 使用模板 B-2（不包含占位符规则）

### 模板 B-1：例文包含实际表格数据

```
任务目标：
基于指定 TFL 表格自动生成 CSR 的[{章节标题}]章节，并输出相关引用及原始表格。

可用工具：
1. Tools -> read_tfl
用途：读取指定 TFL 表格内容。
参数：
- folderPath（必填）：TFL表格文件所在目录路径（见全局配置）
- requirement 或 fileNameHint：查询需求或文件名提示
返回格式：
1、原始Html
2、表格Markdown结果
3、表格的唯一码，用于后续调用
4、表格文件名

2. Tools -> link_tableslisting
用途：根据 read_tfl 返回结果或主表文件路径和列表目录，按文件名匹配对应列表文件，生成引用语句。
参数：
- folderPath（必填）：Listing文件所在目录路径（见全局配置）
- requirement：查询需求描述

执行步骤：
第一步：检索 TFL 表格
调用 Tools -> read_tfl，搜索以下内容的表格（使用requirement参数进行内容匹配）：
- requirement: "{从例文提取的检索关键词}"

注意：
- 使用requirement参数进行搜索，不要使用fileNameHint
- 搜索关键词应基于本章节的数据需求描述，而非具体表名
- 如果搜索结果不匹配，可以调整requirement关键词重新搜索
- 如果检索不到匹配的表格，对应的正文段落应被删除

第二步：分析表格结构，识别数据字段
仔细分析读取到的表格 Markdown 内容，识别以下信息：
1. 表格的列定义（各分组名称、合计列）
2. 表格的行定义（各项统计指标）
3. 表格脚注中的特殊说明

从表格中自动识别并提取数据（根据表格实际内容）：
- {从例文分析出的数据类别，如：药物暴露持续时间、剂量强度等}
- 不要预设具体的药物名称或分组名称，根据表格列定义自动识别
- 不要预设具体的字段名称，根据表格行定义自动识别

第三步：生成[{章节标题}]章节正文

动态段落生成规则：
- 根据实际检索到的表格数量和内容动态生成段落
- 如果某个表格检索不到，对应段落应被删除
- 不要编造不存在的数据
- 根据表格实际包含的字段动态生成描述（不预设字段名称）

正文写作规律：
{从例文提取的写作规则，按以下格式组织：}

1. 按表格/主题组织段落（不是按单个指标拆分）：
   - 如果例文中同一表格的数据在一个段落内，提示词也应该合并为一个段落
   - 如果例文中不同表格的数据分开，提示词也应该分开
   - 段落内的不同指标使用逗号分隔，不要使用空行

2. 每个表格/主题的写作规律：
   - [表格/主题名称]：
     * 包含的指标：[列出该段落包含的所有指标]
     * 写作格式：[整体句式结构，使用通用占位符]
     * 表格绑定字段：[从表格中提取哪些字段]
     * 通用格式模板：[写成完整段落格式，指标之间用逗号分隔]

3. 数据来源：
   - [字段名称]：从表格[行/列定义]中提取
   - ...

第四步：输出 TFL 数据集引用
调用 Tools -> link_tableslisting，搜索与本章节相关的表格的个体数据引用信息。
搜索关键词应基于本章节实际检索到的表格内容。

输出要求：
- 使用表格/图片文件名中的编号（如表14.1.8.1），不使用$TABLE/$IMAGE占位符
- 先列出表格引用信息，再列出个体数据引用信息

第五步：输出原始表格占位符
不要直接展开原始表格 HTML，也不要自行转写表格内容。
规则：
- 正文末尾只插入提供详细数据的表格占位符
- 必须原样输出 read_tfl 返回的 tablePlaceholder/table_placeholder
- 输出占位符前，先输出表格标题，格式为：表* xxx（xxx为表格文件名中的名称）
- 表格标题和占位符要换行写
- 只输出实际检索到的表格的占位符

数据校验规则：
{从 common-rules.md 注入的规则}

异常处理规则：
{从 common-rules.md 注入的规则}

统一写作规则：
{从 common-rules.md 注入的规则}

最终输出格式：
1. 仅输出[{章节标题}]章节正文
2. 如正文确需插入原始表格，仅在正文相应位置输出占位符

最终输出补充要求：
1. 最终结果必须是一个完整 Markdown 文本。
2. 若需要插入原始表格，必须输出工具返回的 placeholder，不得改写占位符文本。
3. 程序会在最后一步执行完成后，将 Markdown 转为 HTML，并用 placeholder 替换为实际 HTML 表格内容。
4. 不要输出类似"TFL 数据集引用""原始表格 HTML 路径""原始表格"之类的标题。
```
